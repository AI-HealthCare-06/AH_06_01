# 데모 계정의 7일 서베이·모델·수면 EXP 검증

2026-10-27 · 브랜치 `feature/pixel-adventure-device-quests`.

## 반영 범위

기존 고혈압·당뇨 합성 페르소나에 오늘까지 최근 7일의 일일 서베이를 추가했다. 혈압·맥박·혈당·수면·활동·좌식·코골이·낮의 졸림·밤중 화장실 응답을 보관한다. 수면은 취침·기상 시각과 일치하고 0점·활동 0분도 결측과 구분한다. 기존 7일 건강 수치는 유지한다. 자료는 가상의 데모 입력이며 환자군의 평균값이 아니다.

데모는 별도 저장소 접두어를 사용한다. 날짜와 fixture revision이 같은 경우 다시 시드하지 않으며, 예전 데모에는 새 revision을 한 번 적용한다. 실제 계정 저장소·약 일정·서버 동의는 수정하지 않는다. 데모의 서버 계정 동기화 호출은 0건이었다.

## 완료·성장 보상

상태값만 완료로 표시하는 방식에서 실제 `completeQuest`와 `recordDailySurvey` 경로로 합성 일주일을 생성하는 방식으로 바꿨다. 서베이 완료, 건강 이력, 4개 메인 퀘스트 진행률 및 수면 보상 원장을 함께 만든다. 오늘은 식사·서베이 2/4 완료이며 별도 수면 퀘스트 완료를 만들지 않는다.

수면 보상은 시간당 기본 20 EXP, 기본 160 EXP 상한과 기존 레벨별 배율을 그대로 사용한다. 대시보드의 선택일 수면과 퀘스트 요약에 실제 지급된 추가 EXP를 표시한다. 아래 최종 EXP는 날짜별 지급 당시 레벨 배율을 반영한다.

| 날짜 | 취침 → 기상 | 수면 | 코골이 / 낮의 졸림 | 기본 EXP | 지급 EXP |
| --- | --- | ---: | ---: | ---: | ---: |
| 2026-10-21 | 00:36 → 06:00 | 5.4시간 | 6 / 5 | 108 | +162 EXP |
| 2026-10-22 | 23:54 → 06:00 | 6.1시간 | 5 / 4 | 122 | +183 EXP |
| 2026-10-23 | 00:12 → 06:00 | 5.8시간 | 7 / 6 | 116 | +261 EXP |
| 2026-10-24 | 23:00 → 06:00 | 7시간 | 3 / 0 | 140 | +315 EXP |
| 2026-10-25 | 23:36 → 06:00 | 6.4시간 | 5 / 4 | 128 | +288 EXP |
| 2026-10-26 | 00:24 → 06:00 | 5.6시간 | 7 / 6 | 112 | +378 EXP |
| 2026-10-27 | 23:48 → 06:00 | 6.2시간 | 6 / 5 | 124 | +418 EXP |

오늘 수면 6.2시간의 기본 보상은 124 EXP, 해당 레벨 배율 적용 후 **+418 EXP**다. 일주일 수면 추가 EXP 합계는 **2,005 EXP**다. 이 금액은 전체 데모 경험치에도 포함된다. 같은 응답 재제출·새로고침은 보상을 다시 지급하지 않으며, 같은 날 더 긴 수면으로 수정하면 기존 최대 지급액보다 증가한 차액만 받는다.

## M1·M2와 Sub Quest

프런트엔드와 모델 서버 어댑터가 같은 `frontend/src/design/demo-persona.json`에서 날짜별 서베이를 만든다. 실제 고정 M1 바이너리의 SHA-256 검증 후 기존 M1·M2를 로컬에서 실행했다. 모델 학습·가중치·임계값은 변경하지 않았다.

- 기준일 및 반영한 일일 서베이: **2026-10-27**.
- M1: 실측 혈압과 고혈압약 복용 페르소나이므로 기존 계약대로 `not_applicable`, 추정 확률 없음. M2 연결 단계는 기존 복약 계약의 `htn`이다.
- M2: `data_quality=ok`, 수면 관련 확인(`NOCTURNAL_SCREEN`) 1개. 자료 대기 5개, 대상 제외 2개를 정상으로 표시하지 않는다.
- 전날 입력: 2026-10-26 수면 5.6시간, 4,700보, 식사·물·서베이 완료. 7일 중강도 활동 합계 90분을 전달한다.
- 추천 순서: 약 / 영양제 복용 → 건강 서베이 → 6,000걸음 걷기. 제거된 수면 퀘스트 추천을 건강 서베이로 바꾸고, 실제 클릭하면 서베이 모달을 연다. 물 마시기는 별도 선택 카드로 유지한다.

공개 데모 API는 기존처럼 고정된 합성 페르소나 ID만 받는다. 브라우저에서 수정한 개인 입력을 익명 모델 API로 전송하지 않는다. 데모 입력 원본의 0~10 점수는 보관하며 현재 모델의 불리언 계약에는 증상 유무만 전달한다.

## 검증

- lockfile의 `npm ci`, 전체 프런트엔드 단위 테스트 **295개** 통과. 날짜 고정 검증 코드 수정 후 관련 5개도 재확인했다.
- 관련 Python 모델 입력·인증·동의 검증 **19개** 통과.
- 관련 브라우저 시나리오 **12개** 통과. 실제 모델 HTTP 응답과 화면 반영, 7일 저장·새로고침, Sub Quest에서 서베이 모달 열기, 저장된 설문 재제출의 중복 EXP·골드 방지를 포함한다. 전체 E2E 묶음을 실행한 것은 아니다.
- lint·format·타입/프로덕션 빌드 통과. 320/390/430px 배치 검증을 포함한다.
- 실제 모델 호출 및 데모 화면 증거는 이 폴더의 `actual-model-response.json`, `verification.json`, `demo-*.png`에 있다. 사용자가 보는 로컬 앱 탭에서도 데모 진입·대시보드·Sub Quest 응답을 확인했다.

## 실행 상태와 배포

이번 변경은 **로컬 구현·검증 완료 상태**다. 공개 AWS 모델 API·공개 웹·Supabase OTA는 새로 게시하지 않았으며 기존 배포 1.5.6을 유지한다. DB 스키마·네이티브 APK 변경은 없다.

현재 로컬 앱은 `http://127.0.0.1:5173`, 합성 전용 모델 서버는 `http://127.0.0.1:8007`에서 실행 중이다. 개발 서버는 `VITE_REXRUN_DEMO_MODEL_API_URL=http://127.0.0.1:8007`로 연결하며 **DEV 빌드에서만** 이를 사용한다. 프로덕션 JS 번들에 이 루프백 주소가 포함되지 않는 것을 확인했다. 모델 서버는 루프백에만 바인딩하고 인증 토큰을 받으면 거부하며 계정 저장소를 읽지 않는다.

재현: 모델 의존성이 있는 Python으로 `python infra/aws/model/serve_demo.py --port 8007`을 실행하고, 위 개발 환경 변수와 기존 개발용 클라우드 옵션으로 Vite를 시작한다. 실제 모델 브라우저 검증은 `REXRUN_DEMO_LIVE_MODEL=1`을 설정한 후 `tests/demo-survey-week.spec.ts`를 실행한다. 일반 CI에서는 고정 응답으로 UI 계약을 확인하고 로컬 실행은 실제 모델 응답을 사용한다.
