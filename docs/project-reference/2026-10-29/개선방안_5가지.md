# 식단 분석과 모션 캡처 개선 후보 5개

확인일 2026-10-29. 아래는 공식 문서와 현재 구현을 바탕으로 한 제안이며 아직 적용하거나 외부 AI 사진·영상 테스트를 실행하지 않았다. 개선 폭·인식률·비용은 실제 사용자 표본으로 비교하기 전에는 확정할 수 없다.

## 현재 코드에서 확인한 한계

식단은 OpenAI gpt-4o-mini 기본 설정, 한 장 사진, 1024px 정규화, JSON object 응답과 개발용 음식 영양 DB를 사용한다. 음식 이름과 중량 인식 오차, DB 매칭/영양 성분 오차, API 지연을 별도로 평가해야 한다. 현재 실제 사용자 정확도 측정값은 없다.

모션은 이미 Web Worker를 사용한다. Face/Hand/Object Detector는 CPU delegate로 동작하고 목표 입력은 최대 10fps, 사물 추론은 최대 5fps다. 물·복약·주사 모두 고정 시간/거리 규칙 중심의 실험적 과정 인식이다. 일반 컵/병 탐지는 알약·주사 도구·실제 삼킴·주입량을 확인하는 모델이 아니다.

| 번호 | 선택할 개선 방향 | 기대하는 변화 | 부담과 한계 |
|---|---|---|---|
| 1 | 식단 VLM 비교와 음식별 고해상도 재확인 | 음식명/반찬 누락·잘못된 출력 감소를 목표로 함 | API 모델별 품질·지연·가격을 같은 사진으로 비교해야 함 |
| 2 | 식단 영양 DB 교체와 실제 섭취량 확인 | 한식 이름 매칭·영양 계산·중량 오차를 분리해 줄임 | DB 연결만으로 음식 식별이나 사진 속 중량이 정확해지지는 않음 |
| 3 | 모션 네이티브 추론과 기기별 지연 최적화 | WebView/CPU 병목과 프레임 손실 개선을 목표로 함 | 네이티브 플러그인 및 APK 변경 필요, 규칙 기반 오탐 자체는 남음 |

### 1 식단 VLM 비교와 음식별 고해상도 재확인

현재 모델을 포함한 후보를 같은 한식 사진으로 비교한다. 전체 사진에서 음식을 찾고 애매한 음식만 확대 재분석하며, 음식명·중량·불확실 사유를 구조화한다. JSON Schema 준수는 파싱 실패를 줄이는 방법이며 인식의 정답을 보장하지 않는다. 사진의 숨은 재료·염분·실제 양은 사용자 확인을 유지한다.

공식 근거: [OpenAI 이미지 입력과 한계](https://developers.openai.com/api/docs/guides/images-vision), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

### 2 식단 영양 DB 교체와 실제 섭취량 확인

현재 개발용 샘플 DB를 식약처 K-FIND 등 출처와 갱신일이 있는 DB로 교체하는 방향이다. 음식 코드·조리 상태·1인분 단위를 구분하고, 밥공기/접시 크기나 중량 직접 입력을 받아 섭취량을 보정한다. 미등록 음식은 비슷한 음식의 영양값을 자동 확정하지 않는다. 제공 DB 필드·갱신 주기와 사용 조건은 연결 시점에 확인한다.

공식 근거: [식약처 식품영양성분 DB 내려받기](https://various.foodsafetykorea.go.kr/nutrient/general/down/list.do), [식품안전나라 데이터활용서비스](https://www.foodsafetykorea.go.kr/api/main.do).

### 3 모션 네이티브 추론과 기기별 지연 최적화

기존 Worker 구현 위에 무조건 Worker를 하나 더 추가하는 제안이 아니다. 실제 Galaxy의 전처리·복사·모델별 p50/p95 지연부터 측정하고, ROI/모델 실행 간격을 조정하거나 네이티브 MediaPipe/LiteRT와 지원되는 가속기를 비교한다. GPU가 항상 빠르다는 전제로 바꾸지 않는다. 입력 손실과 결과 시점이 기존 시간 규칙을 깨뜨리는지 함께 검사한다.

공식 근거: [MediaPipe Web Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js), [LiteRT delegate 평가 도구](https://developers.google.com/edge/litert/performance/delegates).

### 4 모션 전용 도구 탐지와 시간 시퀀스 분류 학습

손·얼굴 랜드마크와 컵/병/알약 근접 영상/인슐린 펜/일반 주사기의 도구 단서를 결합한다. 고정 임계값만으로 결정하는 대신 MoViNet 같은 시계열 모델 또는 랜드마크 시퀀스 분류기를 후보로 평가한다. 빈손·전화·식사·도구만 들기·가림을 음성 사례로 포함하고 같은 사람의 인접 프레임이 학습·평가에 섞이지 않도록 한다.

공식 근거: [MoViNet 스트리밍 동작 분류](https://www.tensorflow.org/hub/tutorials/movinet), [MediaPipe Model Maker](https://developers.google.com/edge/mediapipe/solutions/model_maker).

### 5 짧은 영상 VLM 후검증과 불확실 결과 확인

단말에서 후보 동작 구간만 찾고 동의한 짧은 영상 또는 타임스탬프 프레임을 VLM에 보내 순서를 보조 확인하는 방식이다. 영상 API의 기본 1fps는 빠른 손동작을 놓칠 수 있어 샘플링을 조절해 비교해야 한다. 애매하면 자동 성공 대신 재촬영/직접 확인을 제시한다. 주사 용량·실제 삼킴을 확정하거나 재투약을 유도하지 않는다.

공식 근거: [Gemini 영상 이해와 프레임 샘플링](https://ai.google.dev/gemini-api/docs/video-understanding).

## 고르는 기준

식단 음식명을 자주 틀리면 1, 음식은 맞는데 영양/분량이 이상하면 2가 우선이다. 모션이 버벅거리면 3, 잘못 성공하거나 동작을 놓치면 4, 학습 데이터 없이 과정 검증을 빠르게 비교하려면 5를 검토할 수 있다. 여러 항목을 함께 선택해도 된다.

평가는 식단 음식별 정밀도·누락률·중량 오차·알 수 없음 비율·지연을, 모션은 과정별 precision/recall/F1·오탐/분·미완료율·p50/p95 지연·기기별 FPS를 사용한다. 화면의 confidence나 유효 관찰 비율을 정확도라고 보고하지 않는다.
