# 갤럭시 건강 기능 구현과 테스트

> 2026-10-20 업데이트: 아래는 초기 기기 기능 구현 기록이다. 실제 계정별 서버 저장·로그인·FCM·배포 상태는 [최신 RDB/배포 문서](architecture/SYSTEM_DATABASE_AND_AWS.md)를 따른다. 현재 저장 동의 후 건강/복약/실천 기록을 AWS API와 Supabase에 전송한다.

작업 브랜치는 `feature/pixel-adventure-device-quests`다. 임상 입력과 화면 출력 코드의 최우선 근거는 사용자가 제공한 `docs/toDev`의 혈압 판정 트리 v0.1, 판정 데이터 매트릭스 네이밍 v0.1, 임상 조사 v1.2다. 원본 자료는 수정하지 않는다.

## 반환값 표시 기준

혈압 판정 `bp_band`, Model의 `risk_level`/`risk_index`와 Ranker의 퀘스트 우선순위는 서로 다른 값이다. `domain/risk-presentation.ts`에서 각각 검증한다. 가정혈압 참고 밴드와 단일 설문 측정값을 구분하고, `normal_ref`, `elevated_ref`, `prehtn_ref`는 매트릭스의 `normal`, `elevated`, `prehtn` 별칭으로 표시한다. `insufficient`와 유효 기록 5일 미만은 판정 보류다. 안전 게이트의 재측정·당일 진료·119 코드는 밴드보다 먼저 표시한다. 임의의 확률 경계를 새로 계산하지 않는다. 기존 Model의 등급 경계는 임시 기준이므로 서비스에서 반환한 등급을 참고 지표로만 표시한다.

현재 판정·Model·Ranker HTTP 서비스는 연결되지 않았다. 건강 점수·추이·효과 예측의 Figma 예시는 데모 표시를 유지한다. 실제 반환값이 없으면 결과 대기로 표시하며, 가상의 임상 판정이나 추천 순서를 만들지 않는다. `services/health-profile-payload.ts`는 toDev의 snake_case 입력을 위한 어댑터이며 업로드를 실행하지 않는다. 희귀 질환·특수 이력은 따로 보존하고 일반 성인 모델의 특징값으로 자동 변환하지 않는다.

## 유저와 캐릭터 대시보드

`/dashboard`는 유저의 건강 점수 예시·혈압 기록/판정·Model/Ranker 참고 결과·질환 위험도 예시·기간별 추이를 보여준다. 공룡 성장 카드는 포함하지 않는다. `/dashboard/character`는 선택한 공룡·외형·레벨 경험치·게임 체력·전투 능력치·웨이브 진행·GOLD·퀘스트 버프를 현재 게임 기록에서 계산해 보여준다. 레이더의 과거 비교는 디자인 예시임을 별도 표시한다. 두 경로는 Dashboard 탭의 전환 메뉴로 연결되고, 홈 DINO RADAR와 Character 외형 화면에서도 캐릭터 대시보드로 들어갈 수 있다. 캐릭터 화면에는 건강 기간 달력과 의료 판정/위험도 카드를 표시하지 않는다. 320·390·430px 화면과 6종 캐릭터 변경을 포함한 관련 브라우저 검증 26개 및 lint·format·production build를 통과했다.

## 가입과 복약

설문은 기본 정보 → 혈압/공복 혈당 → 지병/복약 → 생활습관/가족력 네 페이지다. 모르는 값은 null로 남긴다. 지병은 제공 자료 P08 코드와 일반적인 만성질환 목록을 제공하며 직접 추가할 수 있다. 약 이름·처방 용량·약물 분류·복용 시간(하루 최대 6개)을 등록하고 수정·삭제·일시 중지할 수 있다. 하루의 모든 활성 복용 시간을 기록하면 기존 약 복용 퀘스트가 한 번 완료된다. 개별 복용 기록의 중복 보상은 없다. 복용 기록은 자기 보고다.

프로필은 현재 세션 메모리에 유지한다. 약과 복용 기록은 기기의 앱 저장소에 저장하고 로그아웃하면 삭제한다. 계정 서버·의료정보 동기화는 미연결이다. 로그인 자격증명은 저장하거나 전송하지 않는다. 로그아웃은 게임 루프·걸음 동기화를 중단하고, 복약 알림을 취소하며, 재로그인 시 로그아웃 동안의 전투를 소급 계산하지 않는다.

## 갤럭시 걸음 수와 알림

삼성 헬스 → Health Connect → REXRUN의 걸음 수 읽기 순서다. Health Connect의 네이티브 일 단위 합산으로 폰·워치 기록 중복을 방지한다. 읽을 수 있는 기록이 없는 경우 0으로 확정하지 않는다. 오늘 6,000걸음 이상이 읽히면 걷기 퀘스트가 자동 완료된다. 삼성 헬스와 REXRUN 양쪽에 걸음 수 공유/읽기 권한이 필요하다. iOS 기존 어댑터는 유지하되 이번 실기기 검증 대상은 갤럭시다.

복용 알림은 서버 원격 푸시가 아닌 Android 로컬 예약 알림이다. 알림을 켤 때 POST_NOTIFICATIONS와 정확한 알람 설정을 요청한다. 거절하면 권한 상태를 안내하고, 정확한 알람 미허용 시 지연 가능성을 표시한다. 일반 일정 갱신/앱 재개 때 권한을 반복 요청하지 않는다. 알림 본문에는 약 이름·용량을 노출하지 않는다. 알림을 누르면 복약 화면이 열리며, 일정 수정·삭제·로그아웃 시 기존 예약을 취소한다. Android의 Doze·절전·강제 중지·알림 권한은 실기기에서 확인해야 한다.

## 설치용 APK

`frontend`에서 잠금 파일 기준 `npm ci` 후 `npm run native:apk`를 실행한다. JDK 21과 Android SDK 36, Build Tools 및 SDK 라이선스가 필요하다. `ANDROID_HOME`을 우선 사용하고 Windows 기본 SDK 경로를 대체 경로로 사용한다. APK는 `.cache/mobile/rexrun-galaxy-debug.apk`에 생성되며 Git에 포함하지 않는다. 이 APK는 개발 테스트용이고 정식 릴리스가 아니다.

1. 갤럭시로 APK를 옮겨 설치한다. 기존 `com.rexrun.demo` 설치가 있으면 동일 서명에서만 업데이트할 수 있다.
2. 가입하기에서 네 단계 이동·이전 단계 값·희귀 질환과 특수 이력을 확인한다.
3. 헤더의 약 아이콘에서 약과 현재 시각 이후의 복용 시간을 등록한다. 복용 알림과 정확한 알람을 허용한다.
4. 삼성 헬스의 Health Connect 걸음 수 공유와 REXRUN 읽기 권한을 켠 후 다시 동기화한다. 삼성 헬스의 기록과 REXRUN의 오늘 걸음 수·6,000걸음 퀘스트를 비교한다.
5. 화면 켜짐·앱 백그라운드·화면 꺼짐 상태에서 알림을 확인한다. 알림 클릭 시 복약 화면이 열려야 한다.
6. 일정 변경·삭제·알림 OFF·로그아웃 후 이전 알림이 더 이상 전달되지 않는지 확인한다. 로그인 화면에서 기다리거나 앱을 재시작해도 전투 진행/보상이 증가하면 안 된다.
7. 320·390·430px 폭과 기기 글자 확대에서 대시보드 숫자·카드·입력·하단 탭의 잘림을 확인한다.

공식 기술 근거: [Capacitor Local Notifications](https://capacitorjs.com/docs/apis/local-notifications), [Capgo Health](https://capgo.app/docs/plugins/health/), [Samsung Health Connect FAQ](https://developer.samsung.com/health/health-connect-faq.html).

## 2026-10-22 퀘스트 인증 후 완료 · 로컬 데모

`feature/pixel-adventure-device-quests`에서 인증 없는 완료·초과 클리어를 차단했다. 식사는 직접 촬영한 사진 제출, 복약·투약은 각 약·복용 시간에 연결한 사진 제출 후 기록, 물은 실제 카메라의 동작 인식·사용자 확인, 수면은 건강 앱의 오늘 종료된 수면 단계 7시간 이상, 걸음 수는 기존 6,000걸음 연동을 사용한다. 모든 활성 복약 시간 기록이 있어야 복약 퀘스트가 한 번 완료된다. 약이 없는 경우 빈 일정만으로 보상받지 않는다.

화면 버튼과 게임 상태 처리 모두 인증을 검사한다. 사진·모션의 대기 인증은 현재 로그인 세션에서 당일 30분간 유효하고 한 번만 사용한다. 새로운 로그인·로그아웃 시 폐기한다. 초과 클리어도 새 인증이 필요하며 기존 횟수·물 인정 간격은 유지한다. 기존 완료·게임·복약 데이터는 초기화하지 않는다. 완료 결과는 기존 로컬 저장·계정별 전송 경로를 사용한다.

사진·영상은 화면에서만 사용하며 서버로 보내거나 영구 저장하지 않는다. 사진 제출을 확인하는 방식이며 음식·약의 종류 또는 실제 복용 사실을 AI로 판정하지 않는다. 물 동작 인식은 실제 섭취량을 측정하지 않는다. 샘플 모션·사진으로 바꿔 찍는 물 인증은 보상으로 이어지지 않는다. 카메라 권한 거부·연결 종료는 인증을 만들지 않으며 다시 연결할 수 있다.

수면은 읽기 권한만 요청하고 수면 단계 중 깨어 있음·in-bed를 제외하며 겹치는 폰·워치 구간을 합친다. 수면 단계가 없는 단순 침대 체류 시간은 인증하지 않는다. Android READ_SLEEP 권한과 건강 데이터 설명을 추가했다. 기존 설치 APK에는 수면 권한이 없으므로 수면 실기기 연결은 새 APK가 필요하다. 이번 요청에서는 APK·Supabase OTA·AWS를 배포하지 않고 http://127.0.0.1:5173 에 최신 소스의 로컬 데모만 실행한다. 웹에서는 수면 읽기·완료가 잠긴다.

인증 만료·재사용·다른 복약 시간·샘플·로그아웃/계정 변경·수면 중복 및 권한/빈 기록 처리를 포함한 전체 단위 검사 211개와 인증 UI 7개를 통과했다. 사진 UI 검사는 합성 영상 스트림을 카메라 입력으로 제공하고 실제 촬영·제출·활성화·기록 경로를 실행했다. 320·390·430px 인증 화면과 카메라 연결 종료 복구도 확인했다. 실기기 수면 데이터 유입과 모바일 새 APK 적용은 이번 검증 범위에 포함하지 않았다.

## 2026-10-22 S25+ 실제 카메라 추가 확인

최종 1.4.0(9) / Supabase 웹 1.4.2에서 후면 카메라 실촬영 → 3:4 임시 사진 → 제출 → 식사 완료 버튼 활성화를 확인했다. 완료는 누르지 않아 게임 보상·퀘스트 기록·복약 데이터가 바뀌지 않았다. 재시작 시 임시 인증은 삭제됐다. Health Connect 수면 읽기는 허용됐고 반환 샘플 0건에서 완료 잠금을 확인했다. 실제 7시간 이상 공유 기록에 따른 완료 활성화는 여전히 미검증이다. 기존 복약 일정은 이미 완료돼 미완료 복약 인증을 위해 기록을 되돌리거나 시험 일정을 만들지 않았다. 임시 QA 앱과 화면 켜짐 설정을 정리하고 게임을 재개했다.

## 2026-10-22 S25+ 삼성 헬스 수면 공유 설정 확인

S25+의 삼성 헬스 7.1.0.053에서 초기 시작·약관 화면이 표시돼 사용자가 직접 초기 설정을 완료했다. 선택 AI 서비스 개발용 민감정보 동의 팝업은 취소했고, 삼성 클라우드 자동 동기화는 OFF 상태를 유지했다. 실제 헬스 커넥트 설정 화면에서 삼성 헬스의 수면 읽기·쓰기 권한이 ON이고, REXRUN의 수면 읽기 권한도 ON임을 확인했다. 헬스 커넥트의 데이터 및 액세스에는 걸음 수만 표시됐고, 삼성 헬스 수면 상세는 '데이터 없음'이었다.

REXRUN 1.4.0(9) / 웹 1.4.2 자신의 네이티브 Health Connect 접근으로 초기 설정 후 최근 7일을 재조회했다. 수면 읽기는 허용됐으나 수면 세션 전체·삼성 헬스 출처·오늘 종료된 수면·단계 포함 수면이 모두 0건이었다. 원본 수면 시각이나 수치, 사진, 로그인 정보는 보고서로 내보내지 않았고 수면·퀘스트 완료 기록을 작성하지 않았다. 현재 유입 확인의 선행 조건은 삼성 헬스에 실제 측정 기록이 생기는 것이다.

워치·링·Fit을 사용하는 경우 Galaxy Wearable에서 S25+ 연결 → 기기를 착용해 수면 측정 → S25+ 삼성 헬스 수면 화면에서 수면 시간과 단계 확인 → 홈을 아래로 당겨 동기화 → REXRUN 수면 퀘스트의 '수면 기록 연결·확인' 순서로 확인한다. 삼성 헬스 홈 우측 ⋮ → 설정 → 헬스 커넥트에서 수면 공유 상태를 확인할 수 있다. REXRUN은 현재 오늘 종료된 실제 수면 단계를 합산하며 단순 수기 총시간만으로 인증하지 않는다. 실제 데이터가 없는 상태를 테스트 기록으로 채우지 않는다. 별도 삼성 클라우드 업로드나 혈중 산소·코골이·마케팅 동의를 수면 연동 확인 때문에 자동 활성화하지 않았다.

기술 근거: https://developer.samsung.com/health/health-connect-faq.html 및 https://developer.samsung.com/health/blog/en/accessing-samsung-health-data-through-health-connect . 임시 서명 검사 도구는 제거하고 USB 화면 켜짐 설정을 원래 값 0으로 복원했다. 앱 코드는 변경하지 않았다.

사용자는 워치·링·Fit 없이 S25+ 휴대폰만 사용한다고 확인했다. 현재 삼성 헬스→Health Connect→REXRUN의 수면 단계 기반 인증에서는 추가 권한을 켜는 것만으로 기록이 생성되지 않는다. 휴대폰 전용 자기보고 등 대체 수면 인증은 현재 구현돼 있지 않으며 이번 설정 점검에서 완료 조건을 완화하거나 허위 수면 기록을 넣지 않았다.

## 2026-10-22 휴대폰 전용 수면 시간 입력·확인 (웹 1.4.3)

워치가 없는 사용자를 위해 수면 퀘스트에 시간·분 직접 입력과 명시적 사용자 확인을 추가했다. 측정값과 구분해 자기보고임을 표시한다. 오늘의 총수면을 0분 초과~24시간 이내 정수 시간·분으로 입력하고 확인해야 인증된다. 기존 완료 조건인 7시간 이상을 유지한다. 시간 수정·확인 해제 시 직접 입력 인증을 폐기하며, 당일 30분 만료·세션 종료·일회 사용 제한을 공통 적용한다. 완료 버튼은 별도로 눌러야 한다.

완료한 정확한 시간은 기존 `game.sleepHours`에 시간 단위로 저장하며 로컬·계정별 캐시·AWS 수집 API·Supabase `game_saves`와 `daily_quest_progress` 전송 경로를 유지한다. 서베이 수면 응답을 덮어쓰거나 기존 완료 데이터를 초기화하지 않는다. 미완료 인증은 메모리에서만 관리하며 앱 재실행 시 재확인한다. 기존 Health Connect/HealthKit 읽기와 단계 합산·중복 제거·권한 처리 코드는 유지한다. 직접 입력값을 수정하는 것만으로 워치에서 받은 인증을 삭제하지 않는다.

픽셀 스타일의 고대비 카드·48px 입력/버튼·시간과 분 2열 배치를 사용한다. 웹에서도 직접 입력은 가능하며 건강 앱 읽기는 기존처럼 모바일 전용이다. native 1.4.0(9)에 웹 1.4.3을 Supabase 서명 OTA로 배포해 APK를 재설치하지 않는다. DB 스키마·앱 ID·서명·저장 키·건강 권한을 변경하지 않는다.

검증: 변경 파일 ESLint·Prettier, TypeScript/Vite 빌드, 단위 검사 227개, 퀘스트 인증 UI 검사 11개 통과. 320·390·430px 및 S25+ 411px 폭을 확인했다. S25+ native 1.4.0(9)에서 웹 1.4.3 같은 프로세스 자동 적용과 재시작 후 기존 계정·게임·복약·알림 설정의 보존, AWS 200·DB 일치를 확인했다. 실제 계정은 오늘 수면이 이미 완료돼 변경하지 않았다. 같은 기기의 분리된 Chrome 합성 계정에서 동일 1.4.3 빌드로 시간 입력·확인·완료·서버 전송을 수행하고, 독립적인 AWS/Supabase 재조회에서 정확한 7.25시간과 일일 자기보고 완료 기록을 확인했다. 기존 Health Connect 읽기는 정상이며 이 사용자는 휴대폰만 사용해 실제 수면 단계는 0건이었다. 새 양수 워치 기록의 실기기 검증은 포함하지 않았다. 검증 요약은 `deliverables/mobile-ota-1.4.3`에 보관한다.

## 2026-10-22 퀘스트 상세 UI 정리 (로컬 데모)

픽셀 스타일을 유지한 종이 퀘스트 패널로 목표·진행률·인증·보상·완료를 한 흐름으로 배치했다. 퀘스트 이유와 수면 입력/건강 앱 연동 안내는 제목 옆 느낌표 버튼을 통해서만 대화상자로 연다. Escape·확인 버튼으로 닫으면 원래 버튼에 포커스를 돌린다. 기존 큰 이유 카드·‘완료하면’ 제목·고정 여백을 제거하고 7H 목표 배지와 퍼센트를 고대비 색상으로 분리했다.

직접 입력에는 시간/분 범위 힌트, 짧은 실제 수면 확인 문구, 입력 확인 버튼만 남겼다. 범위·자기보고·만료·재확인 안내는 입력 도움말에 보관하고 실제 인증 결과/오류는 계속 화면에 표시한다. 인증 조건·확인 해제·워치 읽기·완료·일회 보상·저장소/서버 계약을 변경하지 않았다. 공통 퀘스트 상세의 인증 영역을 보상/완료보다 먼저 배치했으며 다른 종류의 사진·복약·동작 인증도 기존 경로를 유지한다.

`feature/pixel-adventure-device-quests`에서 변경 파일 ESLint·Prettier와 TypeScript/Vite 빌드, 관련 브라우저 검사 13개를 통과했다. 320·390·430·534px에서 가로 넘침 없음, 목표 배지/퍼센트 명암비 7:1 이상, 느낌표 버튼 44px 터치 영역을 확인했다. 직접 입력 완료·저장·중복 보상 차단·수정/해제 시 잠금·도움말 키보드/포커스·기존 사진/복약 경로 회귀를 검사했다. 개발 서버 http://127.0.0.1:5173/quests/sleep 에 반영했다. 이 UI 정리는 로컬 소스 변경이며 Supabase OTA 버전은 앞서 배포한 1.4.3을 유지한다.

## 2026-10-22 대시보드 바로 기록·복약 카메라 이동 (로컬 데모)

유저 대시보드의 혈압 요약과 상세 건강 보고서에서 ‘혈압 기록’을 바로 열어 수축기·이완기 최근 값을 입력할 수 있다. 형식·정수·순서를 검사하고, 기존 프로필의 혈압 필드만 갱신한다. 설문·복약·게임·온보딩·등록일을 재설정하지 않는다. 혈압만 입력한 미등록 데모 사용자를 전체 건강 정보를 제출한 사용자로 승격하지 않고 별도 입력 플래그로 표시한다. 실제 로그인·프로필·저장 동의가 있는 계정은 기존 profile 변경 구독과 AWS/Supabase 동기화 경로를 사용한다. 로컬 데모 프로필은 기존처럼 메모리에서 관리한다. 이 기능은 최근 혈압 한 쌍을 갱신하며, 새 측정 시계열 테이블이나 7일 평균을 생성하지 않는다.

날짜 설정 토글은 접근 가능한 이름·44px 영역을 유지한 삼각형만 표시하고, 주간 달력은 설정을 접어도 항상 남는다. 기간·기준일·지난 날짜 선택은 유지한다. ‘다음 실천’은 요약과 상세 리포트에서 제거했다. 모바일 리포트는 본문 전체가 한 스크롤 영역에서 흐르도록 바꿔 제목과 점수 카드가 겹치지 않게 하고, 픽셀 테두리·종이/청록색 계층과 고대비 기록 버튼을 유지했다.

복약 관리 화면은 약·시간·알림 관리에 집중하고 오늘의 인증/복용 기록 패널을 카메라 탭으로 옮겼다. 복약 퀘스트의 인증 버튼은 `/camera?quest=medicine`으로 바로 연결한다. 카메라 탭에서 시간별 사진 인증→해당 시간 복용 기록→모든 일정 완료 시 1회 퀘스트 완료를 이어서 수행한다. 사진은 메모리에서만 사용하며 사진 종류·실제 복용을 AI가 판정하지 않는다. 인증 후 기록 링크는 같은 카메라 탭의 복약 패널로 이동한다. 일정/완료 기록 키·약 이름/용량·알림 설정·서버 계약은 유지한다. 다른 시간의 인증, 만료·재사용·중복 완료는 기존 store 검사를 통과해야 한다.

단위 검사 236개(34개 파일), 관련 브라우저 검사 23개, 변경 파일 ESLint·Prettier, TypeScript/Vite 빌드를 통과했다. 320·390·534px 대시보드/리포트와 혈압 입력 창, 320·412px 복약 시간 편집 및 카메라 인증을 확인했다. 인증 없이 복용 기록 차단·각 시간 귀속·마지막 일정 후 단 1회 보상·재로딩 유지·로그아웃 시 중단도 재검증했다. 작업 브랜치는 `feature/pixel-adventure-device-quests`이며 로컬 데모에 반영했다. 실제 계정 값을 입력하거나 실기기/배포 서버 데이터를 변경하지 않았고, 새 APK/OTA·Git 커밋·푸시는 진행하지 않았다.
