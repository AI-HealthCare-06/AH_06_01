# 걸음 수 갱신 주기 · 2026-10-26

작업 브랜치: feature/pixel-adventure-device-quests.

## 동작

- Android 새 APK: 네이티브 StepSync 서비스가 화면에 보일 때 5초, 백그라운드에서 30초 주기로 오늘 누적 걸음 수를 조회한다. 단일 타이머만 사용하며 Health Connect 집계로 폰·워치 중복을 처리한다.
- 사용자가 걸음 수 연결 또는 다시 동기화를 누르면 기존 걸음 수 읽기에 더해 신체 활동 및 Health Connect 백그라운드 읽기를 요청한다. 지원·권한이 없으면 화면이 보일 때 5초 조회를 유지하고 제한을 표시한다.
- 서비스가 동작하는 동안 지속 상태 알림을 표시한다. 로그아웃·연동 해제·앱 작업 제거 시 중단한다. OS가 액티비티만 회수한 경우 서비스는 유지할 수 있지만, 프로세스 종료·강제 종료 후 자동 재시작하지 않는다.
- 시작마다 임의 세션 ID를 생성해 이전 세션·늦은 결과를 거부한다. 최근 조회는 프로세스 메모리에만 보관하며 DB·네트워크에 직접 쓰지 않는다. 기존 게임 저장 경로에서 유효한 오늘 기록을 반영하고 6,000보 이상이면 기존 걷기 완료 처리를 사용한다.
- JavaScript가 중지된 동안에는 네이티브 조회가 계속된다. 앱 복귀 시 다시 즉시 조회하며 보상·게임 저장은 기존 WebView 실행 경로에서 반영한다.
- Android 14(API 34)+의 시스템 Health Connect 및 백그라운드 읽기 지원이 필요하다. 이전 APK·미지원 Android·iOS는 화면이 보일 때 5초 조회만 지원한다. 웹 및 합성 데모는 실제 기기 걸음 수를 읽지 않는다.

## 주기와 배포 제한

30초는 실행 목표 주기이며, 절전·Doze·제조사 제한·권한 철회·강제 종료에서는 지연 또는 중단될 수 있다. 삼성 헬스가 Health Connect에 원본 기록을 보내는 속도를 바꾸지는 않는다. CPU를 계속 깨우거나 절전 예외를 강제로 요구하지 않는다.

네이티브 플러그인·서비스·Manifest 권한이 변경됐으므로 기존 설치 앱에 Supabase 웹 업데이트만 배포해서는 백그라운드 동작이 생기지 않는다. 새로운 네이티브 버전의 서명 APK 및 새 호환 지문이 필요하다. 2026-10-26 native 1.5.0(10)과 서명 OTA 1.5.1을 공개 배포했다. 기존 앱은 새 APK를 덮어 설치한 뒤 추가 읽기 권한을 허용해야 한다. 실제 기기 설치·절전 상태 주기는 미검증이다.

기술 근거: [Health Connect 백그라운드 읽기](https://developer.android.com/health-and-fitness/health-connect/read-data), [health foreground service 조건](https://developer.android.com/develop/background-work/services/fgs/service-types#health).
