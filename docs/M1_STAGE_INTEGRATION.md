## 데이터 흐름

## 2026-10-21 없음 응답과 입력 보완

실제 고정 모델로 지병 없음·고혈압 가족력 없음·음주 0일 입력을 재현했다. 기존 Python 어댑터의 false/0 필터는 정상이며, ‘없음’ 자체가 결측으로 집계되지는 않았다. 다만 기존 프로필의 빈 질환 목록은 화면에서 ‘없음’으로 보여도 명시적인 응답 구분 키가 없었다. 또한 기존 서베이에서 허리둘레·안정 시 맥박·교육 이수 연수를 입력할 수 없었고, 음주 일수를 양으로 바꾸지 않으므로 공복 혈당까지 모르면 결측 플래그가 5개가 되어 insufficient가 발생했다.

- conditionStatus는 none / selected / unknown을 사용한다. none과 기존 빈 목록은 당뇨 진단 없음(false), 실제 unknown은 미입력으로 전달한다. 기존 프로필 편집 시 표시된 없음도 실제 저장 키로 정규화한다. 새로운 양성 질환 선택과 기존 약 목록은 별도로 유지한다.
- 음주량(alcoholWeek), 폭음 여부(bingeMonthly), 허리둘레(waistCm), 안정 시 맥박(restingHeartRate), 교육 이수 연수(educationYears)를 선택 입력으로 받는다. 모르는 값은 null을 유지한다. 음주 0일만 실제 0잔·폭음 없음으로 해석한다. 음주 일수만으로 마신 양을 만들어내지 않는다.
- 11개의 짧은 설문 페이지로 나누고 기존 details JSONB·동일한 AWS 수집 API·사용자 RLS에 저장한다. DB 스키마·동의 정책·랭커 연결은 변경하지 않는다.
- insufficient 응답에 고정 항목명의 선택 필드 missing_inputs를 추가한다. 동일 모델의 실제 결측 플래그를 사용하며 품질 임계값·보정·모델 가중치는 변경하지 않는다. 앱은 부족한 항목과 해당 설문 페이지 링크를 표시한다. 혈압 입력·혈압약 복용의 기존 not_applicable 경로도 유지한다.

Lambda 변경 계획은 기존 리소스 정의를 보존하고 코드 갱신과 그 ARN 참조만 포함하도록 검사했다. UPDATE_COMPLETE, Lambda Active/Successful과 패키지 SHA-256 1a698bbe657653b5de2af4f69bbb261f7c31c8de1855bcd4bd30cb046b595e6e의 일치를 확인했다. 원본 모델 SHA-256과 M1-20261020_150607-nested__base 버전은 유지한다. 새 인프라·IAM 범위·공개 DB 권한을 추가하지 않았다.

합성 계정만 사용한 412×892 Chromium 브라우저에서 설문 작성 → 없음/false/새 항목의 실제 Supabase 저장 → insufficient 및 부족한 항목 표시 → 수정 링크로 이동 → 추가 입력 → 모델 분포 표시 → 로그아웃을 통과했다. 처음 분리한 포트 4182는 서버의 허용 Origin이 아니었으므로 인프라 허용 범위를 넓히지 않고 기존 5173 주소의 별도 테스트 컨텍스트에서 검증했다. 서버 어댑터 10개 검사, 고정 모델 예시·5개 도메인 거부/부분 입력 검사와 없음/미입력 구분을 통과했다. 실제 개인 건강 기록은 읽거나 수정하지 않았다. 모바일 브라우저 검증이며 실제 갤럭시 기기에서 실행한 네이티브 검증과 구분한다.
