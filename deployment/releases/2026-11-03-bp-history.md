# 혈압 측정 분석·이력 수집 릴리스

릴리스 브랜치: `release/1.7-bp-history-20261103` · 기능 PR: [#36](https://github.com/AI-HealthCare-06/AH_06_01/pull/36).

혈압 기록이 있으면 측정값·날짜별 평균·기간 추세를 보여주고, 없으면 생활습관 기반 측정 권고를 보여준다. 설문에 실제 측정 시각·장소·혈압계·자세를 선택 입력으로 추가하고 미확인은 그대로 유지한다. 정정·미측정도 불변 개정으로 보존하며 서버 개정·수신 시각과 기기 대기 이력을 분리한다. 작성 중 최신 측정이 바뀌면 오래된 설문 저장을 차단한다.

M1은 기존 `M1-20261020_150607-nested__base`를 유지한다. 연구 EBM v9·새 미래 혈압 예측을 운영 모델로 활성화하지 않는다. 식단 CV·모션 네이티브 코드·APK 서명과 네이티브 호환 지문은 변경하지 않는다. 이번 APK는 현재 네이티브 `1.7.0 (13)`에 새 웹을 포함하고, 기존 호환 앱에도 서명된 OTA로 같은 화면을 제공한다. 웹 버전·실제 main SHA는 배포 후 공개 `release.json`을 따른다.

## 검증

- 기능 PR CI: Git Flow, 프런트 lint·format·단위·빌드, 브라우저 4분할 전체, Android 컴파일 통과.
- 로컬 전체 브라우저 252개 통과, 계정·배포를 요구하는 opt-in 15개 제외. 별도 클라우드 모의 UI 10개 통과.
- 프런트 단위 364개, 연구 단위 30개, 격리 PostgreSQL 47항목, 배포 가드 6개, 식단 패키징 2개 통과.
- 실제 Supabase PostgreSQL 17.11에서 합성 계정으로 11항목 사전 검증: 개정·재전송·정정·과거 시점·충돌·원본 수정/삭제 및 서버 시각 위조 차단·본인 격리·동의 철회·익명 거절. 전체 트랜잭션을 롤백한 뒤 테이블 부재를 확인했다.
- 실제 PostgREST 동시 요청 검사는 DB 적용 후, 클라이언트 게시 전에 `supabase/tests/bp-journal-live.mjs`로 수행한다. 실제 사용자 기록을 사용하지 않는다.

## 반영 순서와 복구

1. 릴리스 PR을 merge commit으로 main에 반영하고 같은 브랜치를 develop에도 PR로 병합한다.
2. main의 SQL과 원격 dry-run을 대조한다. 기존 `20261019141515`는 no-op 예약 기록이며, 새 `20261102132052`가 혈압 테이블·검증 함수·RPC·RLS를 추가한다. 기존 건강 데이터를 이전·삭제하지 않는다.
3. DB 적용 후 실제 RPC·동시성·권한 격리와 보안 advisor를 확인한다. 새 보안 경고가 생기면 게시 전에 해결한다.
4. 같은 main 커밋의 Actions 검증·APK 빌드·서명·원격 해시 검증 후 웹·APK·설치 페이지·호환 OTA 채널을 게시한다.
5. 공개 출처, 설치 파일, OTA 서명과 데모 화면을 검증한다. 이전 APK·채널·서명 자료를 보존한다.

이력 테이블에 실사용 기록이 쌓인 후 복구를 이유로 DROP하지 않는다. 앱 문제가 생기면 입력을 기기에 보관하고, 호환 수정 커밋을 main PR로 반영해 더 높은 웹 버전으로 배포한다. 모델 예측은 실제 종단 자료·독립 검증이 준비될 때까지 비활성으로 유지한다.
